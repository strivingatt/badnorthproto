## О проекте

Тактическая игра в стиле Bad North на Unity 6 (C#, Built-in RP). Юниты двигаются по сетке, сражаются волнами, ИИ врагов преследует игрока. Камера орбитальная с зумом.

## Жёсткие запреты

1. **`.gitignore` — НЕ ТРОГАТЬ НИКОГДА.**
2. Не менять файлы, не указанные в задаче.
3. Не дублировать формулы из `GridManager` — использовать только его публичный API.
4. Не хардкодить значения, которые можно получить из API.
5. Не создавать instance-материалы без уничтожения в `OnDestroy`.

## Конвенции

- XML-комментарии для публичных методов.
- Русские комментарии внутри методов для нетривиальной логики.
- Guard clauses в начале методов.
- Логи с префиксом класса: `Debug.Log($"[{nameof(this)}] ...")`.
- `[SerializeField] private` вместо `public` для полей инспектора.
- Никаких магических чисел — константы или SerializeField.

## Режим PLAN

**Цель:** анализ, архитектура, декомпозиция. **НЕ писать код.**

- Находи корневую причину проблемы.
- Предлагай план по шагам: какие файлы менять, что менять, критерии приёмки.
- Большие задачи разбивай на пакеты с независимыми коммитами.
- Генерируй промпты для act: контекст → задача → требования → ограничения → формат вывода.
- Если не хватает информации — задавай вопросы, не додумывай.

## Режим ACT

**Цель:** чтение и правка кода.

1. Перед изменением: листинг `Assets/Scripts/`, найти точный путь, прочитать файл.
2. Выводить полный файл, а не diff.
3. После изменения: чек-лист приёмки + список изменённых файлов.
4. Не смешивать несвязанные правки в одном запросе.
5. Не создавать новые файлы без явного указания.
6. Не трогать `.gitignore`, `.git/`, файлы вне `Assets/Scripts/` (кроме явно указанных).
